03 / KIMI CODE × GIT

แก้ได้.
ส่งอย่างมีสติ.

Git คือประวัติของโค้ด Kimi คือผู้ช่วยอ่าน diff, เขียน code และตรวจ test — ไม่ใช่เจ้าของการ merge

~/projects/your-repo
$ git status --short
$ git diff
$ git switch -c feature/checkout
$ git diff --check
$ git add -p
$ git diff --cached
$ git commit -m "feat: add checkout validation"
$ git push -u origin feature/checkout

อย่าให้ “แก้ไฟล์ได้” ถูกตีความเป็น “มีสิทธิ์ push ได้”

A
Working tree → staging

ให้ Kimi สรุปไฟล์และ staged diff ก่อน commit

B
Branch → Pull Request

ทำงานบน branch แยก ให้ owner ตัดสินใจ merge

C
Conflict → evidence

อ่านสองฝั่ง รันทดสอบ และอย่าเลือก ours/theirs แบบเดา

D
Recovery → calm

แยก “push แล้วหรือยัง” กับ “อยากเก็บงานไหม” ก่อน reset

04 / GUARDRAILS

ฉลาดแค่ไหน
ก็ต้องมีราวกันตก

งานเงิน สิทธิ์ ข้อมูลจริง และ production ต้องมี validation กับ human approval แยกจากคำตอบของโมเดล

ดู safety rules ทั้งหมด ↗
01

Least privilege

ให้สิทธิ์เท่าที่งานต้องใช้ แยก read, propose และ execute

02

Deterministic checks

ใช้ test, schema, formula, compiler และ source เป็นผู้ตัดสิน

03

Human approval

ถามก่อน destructive, external, costly หรือ scope-expanding action

04

Recovery path

มี audit log, idempotency, rollback และ kill switch ก่อนปล่อย automation
